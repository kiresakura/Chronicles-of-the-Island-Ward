## 1. 結論先講

COTIW 目前雖然是**像素風基底**，但真正該追求的不是廉價復古，而是：

## **「Q 版廟會像素 × 夜市霓光 × 神壇金漆」**

不是陰暗地牢，不是西式奇幻，不是泛亞洲和風拼貼。

這套 UI 必須讓玩家一眼感受到：
- 這是 **台灣民俗**
- 這是 **手機遊戲，不是桌機移植**
- 這是 **明亮可愛但帶一點神異感**
- 這是 **廟口、香火、紅燈、金箔、霓虹招牌** 的混血語言

一句話定義：

> **Temple Neon Pixel**：以像素素材承接生產效率，以廟會金紅主色建立文化辨識，以夜市青藍霓光做對比，做出「可愛、熱鬧、神秘、好點擊」的手機卡牌 UI。

## 3. 視覺設計原則

### 原則 A：先可讀，再華麗
- 任何戰鬥狀態、數字、卡牌費用、血量都必須 **0.3 秒內可辨識**。
- 華麗效果只能包裹資訊，不能遮蔽資訊。

### 原則 B：亮面主題，不走陰森髒暗
- PRD 已定義為 **Q 版明亮**。
- 可以有妖怪與神異感，但底色應偏節慶、燈火、香火，而不是恐怖片。

### 原則 C：觸控優先
- 所有主要互動元件最小點擊區 **88×88 px（設計稿基準）**。
- 重要按鈕必須有 **按下態、hover/聚焦替代態、disabled 態**。
- 不依賴 hover 傳遞關鍵資訊。

### 原則 D：像素素材 + 現代 UI 骨架
- 角色、敵人、道具、地圖節點可維持像素語言。
- 但 panel、button、progress、overlay 建議採 **像素紋理 + 現代扁平分層**。
- 不要把所有東西都做成厚重像素邊框；那只會顯得廉價。

### 原則 E：金紅是文化主軸，青藍是節奏對比
- 主系統色：香火紅、神壇金、深木黑
- 對比 / 功能色：霓光青、靛藍、玉綠

- **Heal Green** `#5BC777`

#### 中性色
- **Paper Warm** `#F5E7CF`
- **Ash Beige** `#D7C4A5`
- **Smoke Gray** `#8B7C73`
- **Night Ink** `#120A09`

### 4.2 亮度使用規則
- 大面積背景：`Lacquer Black`, `Wood Brown`, `Sign Blue`
- CTA / 主交互：`Festival Red` + `Incense Gold`
- 正向獎勵：`Spirit Jade` / `Heal Green`
- 稀有度高光：`Incense Gold` + `Mystic Purple`
- 負面 debuff：`Danger Crimson`, `Warning Orange`

### 4.3 字體
目前工程已掛 `NotoSansTC-Regular.otf`，開發先沿用。

#### 推薦字體層級
- **標題 / 章節 / CTA**：Noto Sans TC Bold
- **數值 / HUD / 小標**：Noto Sans TC Medium
- **內文 / 說明 / tooltip**：Noto Sans TC Regular

#### 字體規則
- 重要數值可加 1px 深色描邊或陰影
- 小字禁止低對比金色直接壓在複雜背景上
- Tooltip 內文行高至少 1.3

### 4.4 邊框與圓角
- 卡牌 / 主要 panel：12 px 圓角（像素化可做 8/12 階梯感）
- 次級按鈕：10 px
- 小 pill / tag：999 px（膠囊）
- 邊框厚度：2~3 px，重點 CTA 可到 4 px

### 4.5 陰影規範
- UI 主要陰影：`rgba(0,0,0,0.30)`，模糊小，偏貼近面
- 神異高光：金色外發光或青藍小外光，用在 rare / summon / selectable node
- 禁止每個元件都發光。那會變成夜市山寨招牌。

## 5. 像素風執行規則

### 保留像素的部分
- 角色立繪 / 敵人 sprite
- 卡牌插圖
- 地圖節點 icon
- 小道具與掉落物
- 特效碎片（煙、火花、香灰）

### 不必死守像素的部分
- HUD 框架
- Overlay / popup / button / progress bar
- 字體外框與 info chrome
- loading / transition UI

### 具體建議
- 像素圖尺寸以 **2x / 3x 放大後仍清晰** 為準
- UI chrome 可採 **向量形 + 像素紋理疊層**
- 重要 icon 採 SVG 或高解析像素版雙軌供應

## 6. UX 骨架

### 6.1 導航原則
- 主選單：大 CTA（起駕 / 開局）為中心
- 次功能：角色、陣型、收藏、招募、商店在底部宮格
- 戰鬥：
  - 上方 = 對手與回合資訊
  - 中場 = 戰場狀態
  - 下方 = 手牌與出牌主操作

### 6.2 操作優先級
1. 開局
2. 戰鬥出牌
3. 地圖節點選擇
4. 獎勵三選一
5. 商店購買

### 6.3 手機版必守規則
- 主要按鈕不可貼齊瀏海 / 手勢區
- 卡牌拖曳時，手指不得完全蓋住關鍵數值
- 長按卡牌時需彈出清楚 detail overlay
- 地圖節點間連線可細，但可點區域要大

## 10. Aida 實作原則

Aida 開發時請遵守：

1. **先做 token 化**：顏色、圓角、邊框、字級、間距先變成常數/主題資源。
2. **先做共用元件**：按鈕、panel、tooltip、badge、resource bar。
3. **再套進畫面**：不要每個 scene 各寫一套醜東西。
4. **保留低耦合**：盡量別直接破壞 STR 核心 scene 結構。
5. **觸控優先**：所有 hover-only 行為都要有 tap / long-press 對應。

---

## 11. 驗收標準

Aida 完成後，驗收看這五件事：

1. **辨識度**：一眼知道是台灣廟會題材
2. **一致性**：主選單、戰鬥、地圖、商店不是四個不同遊戲
3. **可讀性**：小手機上數值清楚
4. **觸控性**：單手可操作，誤觸低
5. **商業感**：看起來像能上架，不像 game jam 半成品
