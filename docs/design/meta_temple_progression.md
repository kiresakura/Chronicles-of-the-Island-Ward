## 1. 概述：從「解卡」到「修廟」

許多 roguelike 把 meta 貨幣的長線用途設計成「解鎖更多卡片進池」。這套作法有效，但**敘事承載弱**——玩家只是看著一份清單打勾，與世界觀脫節。

《鎮島錄》的世界觀核心是一座**鎮島廟**：它鎮守全島、是玩家每次出巡（run）的起點與歸宿。本作把香火（meta 貨幣）的長線用途重新詮釋為**修復與擴張這座鎮島廟**：

- 每趟出巡帶回**香火**；
- 香火用來**修廟**——修正殿、虎爺殿、籤詩亭、夜市香鋪、戲台、鐘鼓樓；
- 廟越完整 → 開局的**選項**越多（更多神明位、破煞法器進池、開局抽籤改規則、商店更豐富、溫和開局被動……）；
- **但廟的擴張只增加「選項與變化」，不直接堆疊戰鬥數值**——確保 meta 進度不變成 pay-to-win，也不讓老玩家對新玩家形成純數值碾壓。

這讓「長線養成」與「世界觀」合一：玩家不是在打勾解卡，而是在**一磚一瓦把鎮島廟重建起來**，每修好一棟都看得到、用得到、且呼應某個遊戲系統。

> 重要落地誠實聲明：截至 2026-06-06，**只有資料層（`meta_buildings` JSON + 驗證）已完成**。修廟的 **UI、存檔、與各建築 `unlocks` 實際掛接到 run 開局流程的程式，皆尚未實作**，屬 PRD Phase 2。本文件凡涉及「按下修復後會發生什麼」的描述，為**設計意圖**，非既成程式行為。

## 2. 三貨幣表（凍結鐵則）

本作採三貨幣制，職責嚴格分離，**不得混用**：

| 貨幣 | 取得 | 作用域／生命週期 | 用途 | 可否花錢買（IAP） |
| --- | --- | --- | --- | --- |
| **銀兩** | 局內（巡境遇煞、惡煞據點、事件等） | **局內貨幣，戰後歸零**（不跨 run 保留） | 局內消費：夜市香鋪／法器攤採買、移除、即時強化 | 否 |
| **香火** | 完局結算（依路線 `incense_reward_modifier` 加權） | **meta 貨幣，跨 run 永久保留** | **修廟**（本文件全部建築的唯一修復貨幣） | 否（嚴禁販售，見 §6） |
| **元寶** | IAP（真實貨幣購買） | 帳號級，永久 | **僅限外觀類**：角色解鎖、卡背、主畫面裝飾、神明降臨動畫 skin、支持者包等（見 §6） | 是 |

鐵則：

1. **修廟只花「香火」**——香火是「玩出來的」。元寶**永遠不能**拿來修廟或加速修廟。
2. **絕不 pay-to-win**：元寶只買外觀／解鎖／支持，買不到任何影響戰力或進度速度的東西。
3. 銀兩與香火**互不換算**：局內賺的銀兩不會變成香火，香火也不會在局內當戰鬥資源用。

## 3. 修廟建築資料結構（`meta_buildings` Schema）

### 3.1 落地狀態

- **位置**：`external/data/meta_buildings/*.json`
- **狀態**：已建立、已驗證。
- **已建立筆數**：6 棟（見 §4）。
- **載入慣例**：JSON 以 `patch_data` / `properties` 兩層包裹（沿用本專案資料載入慣例）；實際欄位定義於 `properties` 之下。

### 3.2 欄位定義

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `object_id` | String | 建築唯一識別碼（如 `building_main_hall`） |
| `building_name` | String | 建築中文名（如「正殿」） |
| `building_description` | String | 建築敘述文案（對外，世界觀向） |
| `building_effect_summary` | String | 效果摘要（對外，清楚說明修復/升級後玩家得到什麼） |
| `repair_cost_incense` | int | 修復成本，以 **香火** 計（如 300） |
| `unlocks` | Array[String] | 此建築解鎖的能力/內容鍵（如 `["deity_slot"]`），供 Phase 2 掛接 run 開局流程 |
| `max_level` | int | 最高等級（可逐級升級的建築，越高級提供越多同類選項） |
| `is_cosmetic_only` | bool | 是否為純外觀/劇情/音樂建築（`true` 代表完全不影響玩法，僅情懷/呈現） |

### 3.3 真實 JSON 範例（`building_main_hall`，逐字引用磁碟現況）

```json
{
	"patch_data": {},
	"properties": {
		"object_id": "building_main_hall",
		"building_name": "正殿",
		"building_description": "鎮島廟的核心。修復後解鎖更多神明位。",
		"building_effect_summary": "解鎖神明位（請神系統可上場的神明數）。",
		"repair_cost_incense": 300,
		"unlocks": [
			"deity_slot"
		],
		"max_level": 3,
		"is_cosmetic_only": false
	}
}
```

## 4. 六棟建築詳表

| `object_id` | `building_name` | 解鎖內容（`unlocks`） | 效果摘要 | 香火成本 | `max_level` | `is_cosmetic_only` |
| --- | --- | --- | --- | --- | --- | --- |
| `building_main_hall` | 正殿 | `[deity_slot]` | 解鎖更多神明位（請神系統可上場神明數） | 300 | 3 | false |
| `building_tiger_shrine` | 虎爺殿 | `[ritual_tool_ward_break]` | 解鎖破煞法器（如虎牌）進入開局選池 | 250 | 2 | false |
| `building_fortune_pavilion` | 籤詩亭 | `[run_modifier_fortune]` | 開局抽籤，改變該趟 run 的規則 | 200 | 2 | false |
| `building_night_market` | 夜市香鋪 | `[shop_stock]` | 商店（夜市香鋪節點）商品更豐富 | 180 | 3 | false |
| `building_stage` | 戲台 | `[cosmetic, story, music]` | 純外觀／劇情／音樂解鎖 | 150 | 2 | **true** |
| `building_bell_tower` | 鐘鼓樓 | `[start_passive]` | 溫和的開局被動 | 220 | 2 | false |

詳解（含 max_level 的升級語意——設計意圖）：

- **正殿（main_hall）**：廟的核心。每升一級多開神明位，讓「請神系統」能上場更多神明，增加**組合多樣性**（不是直接加數值）。最貴（300），定位為最核心的長線目標。max 3。
- **虎爺殿（tiger_shrine）**：把破煞向法器（如虎牌）放進開局選池。升級擴大破煞法器的可選範圍/出現率。max 2。直接鉤住遶境路線的「破煞」需求（見 §7）。
- **籤詩亭（fortune_pavilion）**：開局抽籤 → 改變該趟 run 的規則（run modifier，類似籤運帶來的玩法變體）。升級增加可抽籤詩種類/同時生效數。max 2。
- **夜市香鋪（night_market）**：讓商店節點商品更豐富。升級進一步擴充商品池。max 3。鉤住遶境的「夜市香鋪／法器攤」節點（見 `pilgrimage_route_system.md`）。
- **戲台（stage）**：**純情懷**——外觀、劇情段落、音樂。`is_cosmetic_only=true`，**完全不影響玩法**。最便宜（150），給玩家世界觀與沉浸的回饋。max 2。
- **鐘鼓樓（bell_tower）**：提供**溫和**的開局被動（start_passive）。措辭刻意保守：「溫和」意味著被動是質變/便利向、而非堆疊戰力的強力數值。max 2。**此棟是最接近紅線的設計，必須嚴守「不加硬數值戰力」**（見 §6 紅線）。

## 5. 修廟與 run 的回饋循環

```
一趟出巡（run） ──結算──▶ 香火（meta） ──修廟──▶ 廟更完整
        ▲                                              │
        │                                              ▼
        └────── 下一趟出巡：開局「選項/變化」更多 ◀── unlocks 掛接開局流程
                       （更多神明位 / 破煞法器進池 / 開局抽籤改規則 /
                         商店更豐富 / 溫和開局被動 / 外觀劇情音樂）
```

回饋循環的設計鐵律：

- **廟越完整 → 開局「選項與變化」越多**：更多神明位（更多組合）、更多破煞法器進池、開局抽籤改規則、商店更豐富、溫和開局被動。
- **但這些都不直接加「數值戰力」**：玩家變強的感受來自「**更多選擇、更多 build 可能性、更多開局變化**」，而非「攻擊力 +X、血量 +Y」這種純數值膨脹。
- **新手友善**：因為 meta 不堆硬數值，老玩家的廟再完整，也只是**選項更多**，不會在同一場景對新手形成數值碾壓；同時也避免「沒練滿 meta 就打不過」的逼課/逼肝壓力。
- **長線目標感**：6 棟建築 × 各自 max_level，提供清晰的「下一個香火該投哪」的長期規劃軸。

## 6. 變現邊界（Pay-to-Win 紅線）

本節為**凍結鐵則**，所有後續設計與商城內容皆不得違反。

### 6.1 元寶（IAP）**可以**賣

| 類別 | 範例 |
| --- | --- |
| 外觀（卡面/介面） | 卡背、主畫面裝飾 |
| 角色解鎖 | 解鎖可玩角色 |
| 神明呈現 skin | 神明降臨動畫 skin |
| 支持向 | 支持者包 |
| 其他純呈現 | 外觀、主題、裝飾類 |

### 6.2 元寶（IAP）**絕不**賣（紅線）

| 紅線項目 | 原因 |
| --- | --- |
| **香火** | 香火是 meta 進度貨幣，賣香火＝賣進度＝pay-to-win |
| **修廟 / 加速修廟** | 修廟唯一貨幣是香火（玩出來的），元寶不得介入或加速 |
| **任何影響戰力的數值** | 攻擊/血量/傷害/抽牌等局內戰鬥數值，一律不可販售 |
| **加速進度 / 跳關 / 體力買通關** | 任何「花錢更快變強或更快推進」的設計 |
| **戰力向法器 / 戰力向 build 元件** | 影響局內戰鬥強度的內容不可直購 |

### 6.3 一句話紅線

> **元寶只買「好看」與「解鎖角色/支持」，買不到「變強」或「進度」。修廟只花玩出來的香火。**

注意 §4 的**鐘鼓樓（start_passive）**與**正殿（deity_slot）**雖透過香火解鎖、屬合法 meta，但設計時仍須自我約束：其效果應停留在「**選項/便利/質變**」層面，不得演變成「開局直接 +數值」的硬戰力，以免從另一個方向破壞「meta 不堆數值」的承諾。

## 7. 與其他系統的鉤點

修廟不是孤立系統，每棟（非純外觀）建築都鉤住一個玩法系統：

| 建築 | `unlocks` 鍵 | 鉤住的系統 | 效果方向 |
| --- | --- | --- | --- |
| 正殿 | `deity_slot` | **請神系統** | 增加可上場神明位 → 更多神明組合（多樣性，非數值） |
| 虎爺殿 | `ritual_tool_ward_break` | **法器／破煞**（並間接連動遶境路線的「煞」） | 破煞法器進開局選池 → 應對高污染路段更有解 |
| 籤詩亭 | `run_modifier_fortune` | **Run 規則／開局變體** | 開局抽籤改變該趟 run 規則 → 開局變化 |
| 夜市香鋪 | `shop_stock` | **遶境「夜市香鋪/法器攤」節點**（見 `pilgrimage_route_system.md` §6） | 商店商品更豐富 → 局內補給選擇更多 |
| 鐘鼓樓 | `start_passive` | **開局狀態** | 溫和開局被動（須守紅線，§6） |
| 戲台 | `cosmetic / story / music` | **呈現層**（無玩法） | 外觀/劇情/音樂 |

跨文件鉤點：

- **虎爺殿 → 破煞法器** 與遶境路線的 `pollution_level`（污染/煞氣）形成「**修廟解鎖解法 → 更敢走高污染高報路線**」的長線正循環。
- **夜市香鋪建築 → 遶境夜市節點**：meta 修廟直接讓 run 內的商業節點更有料，是 meta → run 最直接的鉤點之一。
- **籤詩亭 → run modifier**：把「廟的完整度」轉化為「每趟開局的規則變化」，增加重玩新鮮感（replayability）而非戰力。

## 9. 開放問題（Open Questions）

1. **升級成本曲線**：`repair_cost_incense` 目前是「初次修復成本」。升級到 level 2/3 是固定成本、線性遞增、還是指數遞增？需與香火產出曲線（路線倍率）一起定案。
2. **「溫和開局被動」的硬上限**：鐘鼓樓 `start_passive` 怎麼量化「溫和」？需要一條明文規則（例如「不得提供任何直接 +攻擊/+血量/+傷害數值」）以守住 §6 紅線。
3. **正殿神明位上限的平衡**：神明位增加會否讓 build 過度膨脹、稀釋難度？max_level 3 是否恰當，待玩測。
4. **香火唯一去處的風險**：香火若只能修廟，廟全滿後香火將失去用途。是否需要 endgame 香火回收（如「香火供奉」換外觀、或無限小幅 prestige）？需確認其**不可越線成 pay-to-win 的替代品**或變相數值。
5. **建築解鎖順序/前置**：6 棟是一開始全部可修，還是有前置（例如先修正殿才能修偏殿）？影響新手引導與長線節奏。
6. **`is_cosmetic_only` 之外的外觀掛接**：戲台解鎖的 `cosmetic/story/music` 與元寶商城（神明 skin、卡背）如何分工？哪些走香火（玩出來）、哪些走元寶（買外觀），需劃清以免兩條外觀來源打架。
7. **跨裝置存檔**：meta 進度（香火、建築等級）是否需雲端同步？屬 Phase 2+ 基礎建設問題。
