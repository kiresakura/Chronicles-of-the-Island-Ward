## 1. 概述：為何把「爬塔」改成「遶境」

《鎮島錄》fork 自 Slay-the-Robot（STS 系後代），原始骨架是「玩家由下往上爬一座塔，在分支節點圖上選路，逐層推進直到頂端 Boss」。這套地圖結構本身設計優秀、可玩性高，但**直接沿用會帶來強烈的「換皮感」**——玩家一眼能看穿這是 STS 的台灣外觀貼皮，傷害本作「台灣民俗儀式編排」的世界觀完整度。

本作的核心包裝是**遶境**：神轎出巡、繞行轄境、沿途收妖鎮煞、累積香火、最終舉行鎮煞大醮。遶境在文化語感上**天然就是一條由起點走到終點、沿途有不同據點與遭遇的路線**——這與 STS 的「一張由下往上、節點分支、單向推進」的有向圖在拓樸上高度同構。因此我們的策略是：

- **保留底層拓樸與數值節奏**（分支選擇、風險／報酬權衡、Boss 收尾），確保戰鬥手感與 roguelike 樂趣不流失；
- **替換整層語言、視覺與敘事框架**，讓「爬塔」徹底消失，玩家感知到的是「我在規劃一次出巡的遶境路線」。

換句話說：**地圖的「骨」沿用 STS，地圖的「皮與魂」改寫成遶境。** 本文件定義這層改寫的規格與設計意圖。

> 重要落地誠實聲明：截至 2026-06-06，**只有資料層（`route_traits` JSON + schema 驗證）已完成**。把 STS 分支圖實際替換成遶境路線、並套用污染度／香火回報／危險度去驅動節點生成的**地圖生成演算法尚未實作**，屬 PRD Phase 2。本文件中凡涉及「如何生成」「如何放置節點」的內容，皆為**設計意圖（intent）**，非既成程式行為。請勿據此認為地圖已重寫。

## 2. 完整語言轉換對照表

下表為**凍結規格**：所有面向玩家的文案、UI 標籤、敘事用詞，一律採右欄遶境語感，左欄 STS 術語僅供開發內部對照，不得外露。

| STS 原術語 | 遶境語言（對外） | 語感說明 |
| --- | --- | --- |
| Run | 一次出巡／巡境 | 一趟完整的神轎出巡，從起駕到入廟（一局） |
| Act | 章節遶境 | 出巡中的一個大段落／一個轄境章節 |
| Map | 遶境路線 | 玩家在節點圖上選路規劃的整條路線 |
| Combat | 巡境遇煞 | 沿途遭遇妖煞、需出陣處理的戰鬥 |
| Elite | 惡煞據點 | 盤踞一方的強力凶煞，難度高、報酬高 |
| Shop | 夜市香鋪／法器攤 | 可消費銀兩採買法器、香火相關品的商業節點 |
| Rest | 入廟安神 | 進廟休整、安神、恢復或強化的休息節點 |
| Event | 民俗問事／禁忌遭遇 | 抽籤、問事、犯禁忌等敘事抉擇節點 |
| Boss | 鎮煞大醮 | 章節終點的大型鎮煞儀式，最終對決 |

對照原則：

- 「煞」是本作對敵人的統稱意象（妖、煞、怨、邪），「遇煞」「惡煞」「鎮煞」一脈相承。
- 「香火」貫穿整個變現與長線系統（見 `meta_temple_progression.md`），路線層用 `incense_reward_modifier` 控制每條路線的香火產出傾向。
- 「入廟安神」對應休息，呼應「廟」作為玩家的長線據點（meta 修廟系統）。

## 3. `route_traits` 資料結構（Schema）

### 3.1 落地狀態

- **位置**：`external/data/route_traits/*.json`
- **狀態**：已建立、已通過 `test_ritual_schema.gd` 驗證。
- **已建立筆數**：4 條（見 §4）。
- **載入慣例**：JSON 以 `patch_data` / `properties` 兩層包裹（沿用本專案資料載入慣例）；實際欄位定義於 `properties` 之下。

### 3.2 欄位定義

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `object_id` | String | 路線唯一識別碼（如 `route_haunted_house`） |
| `route_name` | String | 路線中文名（如「荒宅路」） |
| `route_flavor` | String | 風味／主題標籤（`mountain` / `temple` / `night_market` / `haunted`），用於選圖、美術、敘事與節點權重 |
| `route_description` | String | 路線敘述文案（對外） |
| `pollution_level` | int | 污染度——該路段的「煞氣／怨氣濃度」，越高代表遭遇越凶、負面遭遇越多（設計軸見 §5） |
| `incense_reward_modifier` | float | 香火回報倍率——影響該路線結算給予 meta 貨幣「香火」的倍數（如 `1.5` = 1.5 倍） |
| `danger_rating` | int | 危險度——綜合戰鬥強度／風險評級，驅動敵人池與節點難度（設計軸見 §5） |

### 3.3 真實 JSON 範例（`route_haunted_house`，逐字引用磁碟現況）

```json
{
	"patch_data": {},
	"properties": {
		"object_id": "route_haunted_house",
		"route_name": "荒宅路",
		"route_flavor": "haunted",
		"route_description": "廢宅怨氣最重。高污染、高危險，但香火回報最豐。",
		"pollution_level": 4,
		"incense_reward_modifier": 1.5,
		"danger_rating": 4
	}
}
```

## 4. 四條路線特徵表（現有資料）

| `object_id` | `route_name` | `route_flavor` | `pollution_level` | `incense_reward_modifier` | `danger_rating` | 定位 |
| --- | --- | --- | --- | --- | --- | --- |
| `route_mountain_path` | 山路 | `mountain` | 2 | ×1.0 | 2 | 標準基準線（balanced baseline） |
| `route_temple_path` | 廟路 | `temple` | 1 | ×0.8 | 1 | 安全、低風險、低報酬（穩健路） |
| `route_night_market` | 夜市路 | `night_market` | 1 | ×1.3 | 2 | 商業節點密集、香火回報偏高 |
| `route_haunted_house` | 荒宅路 | `haunted` | 4 | ×1.5 | 4 | 高危高報（豪賭路） |

設計對照解讀：

- **山路**是三軸的中位基準，其他路線都相對它做加減，方便調平衡。
- **廟路**走「拿命換安穩」相反方向：危險低、香火也低（×0.8），給保守玩家或低血量收尾用。
- **夜市路**用低污染＋偏高香火＋較多商業節點，做為「補給／經濟」取向路線。
- **荒宅路**是極端豪賭：污染 4、危險 4，但香火 ×1.5，獎勵玩家承擔風險。

## 5. 三軸如何影響節點生成與獎勵（設計意圖；演算法 Phase 2）

> 以下為**設計意圖**。對應的地圖生成演算法尚未實作，數字為設計傾向而非已實作公式。

### 5.1 污染度 `pollution_level`（煞氣濃度）

象徵該路段的「邪氣／怨氣」濃度。設計意圖：

- **節點型別權重**：污染度越高 → 「巡境遇煞」「惡煞據點」「禁忌遭遇」等負面/戰鬥節點權重上升；「入廟安神」「夜市香鋪」等正面節點權重下降。
- **遭遇染色**：高污染路段的敵人帶更多 debuff／怨氣機制；民俗問事節點更容易抽到「犯禁忌」的不利結果。
- **與香火的張力**：污染常與香火回報正相關（越髒的地方鎮起來越值錢），形成「乾淨安全 ↔ 骯髒高報」的核心抉擇軸。

### 5.2 香火回報倍率 `incense_reward_modifier`（meta 產出）

控制該路線結算時換算給 meta 貨幣「香火」的倍數。設計意圖：

- **結算乘數**：一趟出巡（run）結束時，依走過路段的香火倍率對最終香火結算做加權（具體聚合方式——逐段加權 vs. 取主路線——Phase 2 決定，見開放問題）。
- **長線驅動**：香火唯一用途是 meta 修廟（見 `meta_temple_progression.md`），因此本倍率是「玩家願不願意為了長線進度去走險路」的關鍵旋鈕。
- **不影響局內戰力**：香火是 meta 貨幣、戰後結算，**不會**在局內變成戰鬥資源，避免高報路線同時等於高即戰力。

### 5.3 危險度 `danger_rating`（戰鬥強度評級）

綜合戰鬥難度評級。設計意圖：

- **敵人池選擇**：危險度決定該路段抽取的敵人/惡煞池強度檔位。
- **節點密度與強度**：高危險路段戰鬥節點更密、惡煞據點出現率更高、Boss（鎮煞大醮）前的鋪陳更硬。
- **與污染度分工**：`pollution_level` 偏向「氛圍／負面遭遇/染色」，`danger_rating` 偏向「純戰鬥強度檔位」。兩者可同高（如荒宅路 4/4）也可錯開，給調平衡留空間。

### 5.4 三軸協同總表

| 軸 | 主要影響面 | 高值傾向 |
| --- | --- | --- |
| `pollution_level` | 節點型別權重、遭遇染色、禁忌結果 | 更多戰鬥/負面遭遇、敵人帶怨氣機制 |
| `incense_reward_modifier` | 結算香火（meta） | 修廟更快，但不增即戰力 |
| `danger_rating` | 敵人池強度、戰鬥密度 | 更硬的戰鬥、更多惡煞據點 |

## 6. 節點型別對照（遶境節點）

| 遶境節點 | 對應 STS | 玩家在此做什麼 | 主要產出 |
| --- | --- | --- | --- |
| 巡境遇煞 | Combat | 出陣處理沿途妖煞 | 銀兩、法器、推進 |
| 惡煞據點 | Elite | 挑戰盤踞的強力凶煞（高風險） | 較佳法器/獎勵、較高銀兩 |
| 夜市香鋪／法器攤 | Shop | 花**銀兩**採買法器、香火相關品、移除 | 補強牌組/法器 |
| 入廟安神 | Rest | 休整、回復、或進行升級/強化動作 | 恢復、強化 |
| 民俗問事／禁忌遭遇 | Event | 抽籤、問事、面對禁忌的敘事抉擇 | 隨機正/負面結果 |
| 鎮煞大醮 | Boss | 章節終點的大型鎮煞儀式對決 | 章節結算、重大獎勵 |

備註：

- 夜市香鋪消費的是**銀兩**（局內貨幣，戰後歸零）；香火（meta）不在局內花用。詳見 `meta_temple_progression.md` 三貨幣鐵則。
- meta 修廟的「夜市香鋪」建築（`building_night_market`）可讓此商業節點商品更豐富——這是 meta → run 的鉤點之一。
- meta 修廟的「虎爺殿」（破煞法器）、「籤詩亭」（run modifier）會分別影響開局選池與規則，間接改變玩家對路線的取捨。

## 7. 第一章「山林遶境」示意

> 此為示意（illustrative），用以說明三軸如何在實際章節中組裝。確切節點佈局由 Phase 2 地圖生成器產出。

**主題**：出巡起駕，神轎入山林轄境，沿途收妖，最終於山中古廟前舉行鎮煞大醮。

- **基調路線**：以 `route_mountain_path`（山路，污染 2／香火 ×1.0／危險 2）為章節基準骨幹，符合「第一章＝標準難度教學坡度」。
- **分支點綴**：在分支處可插入 `route_temple_path`（廟路，安全低報）作為穩健支線、`route_night_market`（夜市路）作為補給支線；`route_haunted_house`（荒宅路，高危高報）作為**選擇性險路**（第一章可低機率出現或作為支線誘餌，正式高危內容留待後續章節）。
- **節點節奏（示意）**：
  - 早段以「巡境遇煞」建立戰鬥手感，穿插一個「民俗問事」做敘事與抉擇引入；
  - 中段提供「夜市香鋪」補給點與一處「入廟安神」；
  - 中後段放置「惡煞據點」作為章節難度檢核（gate check）；
  - 終點為「鎮煞大醮」（章節 Boss）。
- **三軸感受**：第一章整體維持中低污染與中低危險（教學友善），但**已讓玩家看見荒宅路那種「污染 4／香火 ×1.5」的高報誘惑**，預埋後續章節的核心抉擇張力。

## 9. 開放問題（Open Questions）

1. **香火聚合方式**：一趟出巡走過多個路段時，`incense_reward_modifier` 是「逐段加權累加」、「取走過路段平均」，還是「以主章節路線為準」？影響香火經濟曲線，待 Phase 2 數值定案。
2. **污染度與危險度的職責切割**：兩軸目前語意有部分重疊（高污染常伴高危險）。是否需要明文規定「污染只動氛圍/負面遭遇、危險只動戰鬥檔位」，避免調平衡時互相干擾？
3. **路線解鎖條件**：四條路線是否一開始全開？荒宅路（高危高報）是否該由 meta 進度（例如某棟建築或某章通關）解鎖，避免新手早期被高報誘餌帶崩？
4. **每章可走幾種路線風味**：單一章節是固定一種 `route_flavor` 為主，還是允許多風味混搭分支？牽涉美術成本與節點權重設計。
5. **污染度是否有跨節點累積效應**：是否需要「走越多高污染段、後續遭遇越凶」的累積機制（類似 STS ascension 內感受），或維持每段獨立？
6. **與 meta 鉤點的數值邊界**：`building_night_market`（商店更豐富）等 meta 解鎖如何作用於路線節點，且須確保**不越線成 pay-to-win**（meta 只增「選項豐富度」，不直接加戰力數值）——具體上限待 Phase 2 與 meta 設計對齊。
